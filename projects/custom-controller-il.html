02 — DEEP DIVE

Custom Controller for Imitation Learning

ROS2 ros2_control Imitation Learning Policy Deployment

The Challenge

Imitation learning policies output joint-space or task-space commands at high frequency, but the standard ros2_control controllers are designed for trajectory following — they expect pre-planned paths with time parameterization. There was no clean way to stream learned policy outputs directly to hardware while maintaining safety limits, joint constraints, and smooth actuation.

The Implementation

  • Built a custom ros2_control controller plugin that accepts streaming command inputs from an IL policy at the control loop rate
  • Implemented a command interface that bridges the gap between policy inference (running on GPU) and hardware actuation (running in the real-time control loop)
  • Added configurable safety layers — velocity limits, acceleration limits, joint boundary checks — applied at the controller level before commands reach hardware
  • Designed a smooth transition mechanism to switch between traditional trajectory controllers and the IL controller without stopping the robot
  • Integrated with the existing CPDS manipulation stack so IL-based behaviors could be composed with deterministic ones

Key Design Decisions

  • The controller runs in the real-time thread while policy inference runs asynchronously — a lock-free ring buffer bridges the two
  • Fallback to the last safe command if policy inference misses a deadline, preventing jerky motion
  • Configurable interpolation between policy output and current state for smooth startup and handoff

Outcome

Enabled the team to deploy imitation learning policies directly on the physical robot with hardware-level safety guarantees. This became the foundation for exploring learned manipulation behaviors alongside the existing deterministic pipeline — the robot can now seamlessly blend planned motions with learned ones.
